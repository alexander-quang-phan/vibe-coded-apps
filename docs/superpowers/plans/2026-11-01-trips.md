## Assumptions (each could make this plan wrong)

- **A1.** The live DB still has 012/018/018a/019 unapplied, 017a applied, no trip objects. Editing
  018/018a/019 in place is only safe if that holds. *Check:* step 0. If 018 or 018a shows applied →
  STOP and re-plan the trip columns as new migration files.
- **A2.** A bare-PostgreSQL replay of 001→017b works against stubs. No test has ever done it. *Check:*
  step 5. If an older migration fails to replay, record it (BUGS-FIXED 2026-09-23 #4 shape) and tell
  Alex before patching it.
- **A3.** Spec claims checked TRUE against the code:
  - `TX_LIST_COLUMNS`/`TX_WRITE_COLUMNS` exist (routes/transactions.js:28–31), not exported.
  - `encodeWrite` is per row (lib/encryptionCodec.js:132). An array is silently mangled into
    `{0:…,1:…}` even at phase `off`, and the fake accepts it — so the array guard matters in every phase.
  - The harness supports `.in`, `.is`, `.not(col,'is',null)`, `range`, `count`/`head`, `maxRows`,
    `failOn(table, op)` and `upsert`. It has NO `.or`, no `.ilike`, and no FK/CHECK/cascade emulation.
    `failOn` fires on every matching call ("fail only the 2nd update" needs a counting closure).
  - Registry: 17 fields on 10 tables → 22 on 13 after this phase.
  - Runbook counts at lines 36, 185, 210 (lines 41/54 are a dated snapshot — leave them).
  - `progressTone` is in pages/Budgets.jsx:30 (two other tone copies: CategoryDonut.jsx:5,
    SimpleMonthCard.jsx:91).
  - Quick Add reset effect: QuickAddDialog.jsx:79–102, deps `[open, initialDate, currency]`;
    `handleCategoryTap` :317, `handleSimpleLog` :363.
  - Desktop nav `md:flex`/`md:hidden` (App.jsx:112/164); the timezone PATCH invalidates only `['me']` (:65).
  - `DASH_TX_COLUMNS` (dashboard.js:19) lacks `trip_id`. Special groups already collect `dates` per group
    internally (specialGroups.js:63–71).
- **A4.** Where the spec is wrong or stale:
  - (a) The devMock `?month=` bug is already fixed (BUGS-FIXED 2026-10-14). Don't redo or re-log it.
  - (b) `CategoryDialog` (CategoryManager.jsx:59) isn't exported and only shows a form (`onSubmit`, no
    create call). So TripEditor owns `POST /api/categories` and selects the returned id; `lockType` hides
    the Spending/Earning switch.
  - (c) PaceLine is not on the Budgets page — it's in AffordabilityCheck.jsx:86 and SimpleMonthCard.jsx:140.
    The "tracked on its trip" line goes on Budgets.jsx AND inside PaceLine.
  - (d) Quick Add's rate effect (:109–139) clears the rate on every currency change; a remembered rate
    means changing that effect, not adding one (Q5).
  - (e) The Edit dialog ALWAYS sends `isSpecial`, and `specialGroupId` for special rows
    (Transactions.jsx:337–338). "Only when changed" therefore changes non-trip edits too (intended).
  - (f) `GET /api/trips`'s lean query must also select `id` (paging orders by `date, id`, dedupes by id).
  - (g) `readAllPages` is private to subscriptions.js:136 — extract it, don't copy it (shape #1).
  - (h) The /track rollback (subscriptions.js:489) only clears `recurrence_id`; once linking also clears
    `trip_id`, a race rollback would silently strip trip tags (Q2).
  - (i) "Restore on real PostgreSQL" can't run the route (no PostgREST); it runs the route's single UPDATE
    as SQL and checks the CHECKs and resulting state.
- **A5.** The dev client logs in through real Supabase Auth, and agents can't log in. The click-through
  reuses Phase 17's throwaway preview entry (`client/preview.html` + `client/src/preview.jsx`, cache
  pre-seeded from mock payloads, mutations to :3001). Never `git add`ed; deleted at step 22.
- **A6.** The reset effect can't depend on trips data (shape #8). It reads
  `queryClient.getQueryData(['trips'])`. The later-changes effect must skip the commit in which the reset
  ran (a ref the reset sets) and must be idempotent. *Check:* the "log two in a row" click-through.
- **A7.** `PATCH /api/trips` is not atomic (validate → deletes → updates → inserts → trip row). Accepted
  for v1: on error the editor invalidates `['trips', id]` and says "Some changes may have saved — check,
  then save again".
- **A8.** `client/package.json` is `"type":"module"`; `QUOTABLE_CURRENCIES` has 31 entries.
  `client/src/lib/trips.js` stays free of `@/` imports so server tests can import it.
- **A9.** Decrypted amounts may come back as strings; lib/trips.js wraps every amount in `Number()`.
- **A10.** Baseline 722 tests. `[phase=off] preview: the dialog's typed DATE…` can hang under load; re-run
  its file alone before treating it as a failure.

## Writer table (every path that writes trip_id / trip_stop_id / is_special / special_group_id)

| Writer | Writes | Rule it must enforce |
|---|---|---|
| POST /api/transactions — both Quick Add paths | all 4 | Expense only; trip owned; stop belongs to trip; stop needs trip; `tripId`+`groupId` → 400; group omitted → null; `isSpecial` absent + keep-out → true, else `isSpecial ?? false`; derived stop → null |
| PATCH /api/transactions/:id — Edit, row star, "Not trip spending" | all 4 | Resulting state; star derived only when `trip_id` changes AND `isSpecial` absent; join keep-out → true; join keep-out-off → unchanged; leave keep-out → false; trip change without stop clears stop; trip+group → 400; type → income on a trip → 400 |
| POST /subscriptions/:key/attach | `recurrence_id`, `is_recurring`, trip/stop → null, star false only if trip was keep-out | Filter on the `trip_id` it read |
| POST /subscriptions/track (+ rollback) | link clears trip/stop; 2nd update un-stars returned keep-out ids | Un-star after the race re-check; rollback restores tags; `unstarFailed` |
| detach, DELETE /subscriptions/:key | `recurrence_id` only | Must not touch trip fields |
| Nightly cron | DB defaults | Children never trip-tagged or starred — unchanged |
| POST /api/trips/:id/transactions | `trip_id`; star true only for keep-out | One conditional statement, ≤100 ids, no city writes |
| POST /api/trips/from-group | `trip_id`, group → null, star = switch | Group owned; one statement, expenses only; move fails → delete trip; setting on |
| DELETE /api/trips/:id?expenses= | count / keep / restore columns | One statement per mode; restore only with a surviving owned group; then unarchive, then delete |
| PATCH /api/trips/:id — keep-out | star = new value | Only when it differs; transactions first, trip row last; setting on |
| PATCH /api/trips/:id — stop removed | `trip_stop_id` → null | Before deleting the stop; scoped by user and trip |
| DB FK actions (017b, 015) | set null on trip/stop/group delete | Never cascade spending; XOR always holds |
| Categories DELETE reassign | `category_id`; cascades `trip_category_budgets` | Q4 |
| devMock mirrors of all of the above | same | Same guards and messages; imports lib/trips.js |
