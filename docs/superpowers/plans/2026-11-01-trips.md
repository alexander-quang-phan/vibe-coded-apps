## Decisions taken in this plan (technical; spec-compatible)

- **Q1** Start-from-group reads a `dates` array on `GET /api/special-groups`, which moves to the extracted
  `readAllPages` so `dates` and "N outside the dates" can't be cut off by the row cap.
- **Q2** /track un-stars only **after** its race re-check passes; its rollback restores
  `trip_id`/`trip_stop_id` per (trip, stop) pair with `.is('trip_id', null)` (stars need no restore).
- **Add expenses selection** = ticked ∩ currently shown (BUGS-FIXED 2026-10-14 #2: nothing hidden is
  ever submitted). Add in batches.
- **Archived trips:** the server accepts an owned archived trip (re-sending the row's own trip must work;
  PATCH is how you unarchive); the UI never offers one as a new target, and TripDetail hides "Add
  expenses" and the preset Quick Add while archived.
- **Merge hygiene:** the trip rules for transactions live in a new pure `server/lib/tripRules.js`
  (`deriveTripWrite`), imported by the route **and** devMock, so `routes/transactions.js` edits stay to the
  schemas, the existing-row select and one call (it neighbours `/parse`, which the unmerged
  `claude/zealous-poitras-ae4776` edits). Budgets.jsx: remove `progressTone` (:30) + one import, and put
  the trip line near the header, away from the weekly-card fix (~207). Re-run `encrypt-backfill.test.js`
  after that branch merges (step 6 changes the registry, hence the backfill JOBS).

## Open questions (for Alex) — answers recorded here once given

- **Q3.** Subscription charges on trips: block them everywhere (POST `recurring`+`tripId` → 400; PATCH
  `tripId` on a linked row → 400; bulk-tag and from-group skip linked rows; "Repeat this" hidden while a
  trip is attached; the Edit dialog's trip picker disabled for linked rows)? *Recommend yes* — the spec
  already takes them off trips on attach/track and hides them from Add expenses; these are the paths that
  still leak. Cost: small (≈1 rule in tripRules.js, 4 tests, 2 client conditions).
- **Q4.** Deleting a category silently deletes its trip budget lines (the spending moves; only the line
  goes). Monthly budgets already behave exactly this way. *Recommend: document it as a known limit*,
  matching monthly budgets. Alternative: count the lines in the 409 and move them on reassign (adding
  amounts on a clash) — touches the categories route, devMock, categoriesRouteSuite ×3 and the reassign
  dialog.
- **Q5.** The 30-day remembered rate: *recommend only when Quick Add seeds a stop's currency* (the spec's
  scope), while remembering every successfully fetched rate. "Every entry" would let a manual EUR pick at
  home log on a rate up to 30 days old if a chip is tapped before the refresh lands.
